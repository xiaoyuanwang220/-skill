# 区域地理实习记录

## 概述

**输入**：用户在对话中口述的当天实习见闻（走了哪条线路、老师讲了什么、自己观察到什么、有什么疑问）+ 现场照片。

**辅助材料**（放在用户自己的 ima 知识库里）：老师讲解录音（知识库自动转写）、实习指导书、动员大会 PPT、《实习过程记录》模板。

**输出**：按模板排版的 Word 文档，可直接提交。

核心原则：**用户口述是主线，其余材料是核对与补全工具**。不要把成文任务变成"转写稿的二次搬运"。

## 首次使用：定位资源、建立站点索引（只做一次）

新用户第一次对话时执行以下四步，做完在对话里留一份简短记录，后续会话按需复用。

### 1. 定位知识库与关键文件

问用户知识库名称（默认"区域地理实习"），检索其中：

| 需要定位 | 检索关键词 | 要拿到的 |
|---|---|---|
| 知识库本身 | 知识库列表 | `kb_id` |
| 《实习过程记录》模板 | `实习过程记录`、`模板` | media_id、表格结构 |
| 《实习指导书》 | `指导书`、`实习指导书` | media_id |
| 动员大会 PPT | `动员`、`大会`、`PPT` | media_id（可选，没有就跳过） |

检索用知识库搜索能力；读全文用按 media_id 取回。**拿到的 ID 如果环境允许写入，就记到 `references/kb-resources.local.md`**（自己新建），下次直接读；不允许写入则在当次对话内记住，下次重新检索一遍即可。

同时从指导书和 PPT 里读出并**向用户确认**这三项，确认后固定下来：

- 项目名称（如"区域综合地理实习"）
- 专业年级口径
- 带队/授课老师姓名列表（指导书与 PPT 里通常有；仍不确定就直接问用户）

### 2. 清点材料齐备度

对照下表告诉用户缺什么、为什么需要，不阻塞流程：

| 材料 | 是否必需 | 缺失后果 |
|---|---|---|
| 实习记录模板 | 必需 | 无模板无法保证格式，只能按参考结构排 |
| 实习指导书 | 必需 | 站点背景与"思考问题"缺失，"发现的问题"只能用口述内容凑 |
| 老师讲解录音 | 重要 | 细节、术语原话、师生问答会变薄 |
| 动员大会 PPT | 可选 | 项目背景与实习目标口径需用户在对话里补一句 |
| 现场照片 | 可选 | 走模式 A（占位版），后续补图 |

### 3. 从指导书重建"行程—站点—思考问题"索引

**不要用别人那一届的行程表**。首次使用时从用户自己的指导书正文里抽取，整理成下表，作为后续每天写记录时的定位与素材库：

| 天数 | 日期 | 行程（出发地→宿地） | 主要实习内容 | 站点 | 指导书对应"思考问题" |

抽取规则：

- 逐日行程优先取指导书里的行程安排表；没有表就按正文的日程叙述顺序还原。
- 每个站点把指导书里给的**思考问题/思考题**原文摘出一到四条，这是后面"发现的问题"最直接的素材。
- 指导书只给站点清单、没给日期时，天数由用户口述的当天行程确认，不要自行推定。
- 索引**落盘为 `references/itinerary.local.md`**（环境可写时），标注来源指导书的日期与版本；指导书换版本就整份重生成，不要打补丁。
- 索引和录音/口述冲突时，一律以当次实际为准（见下节优先级），索引只用来问"这个站点指导书让你思考什么"。

### 4. 告知用户怎么开始

用两三句话说明：把当天录音传到知识库（文件名 `第X天_地点`）→ 在对话里说一下今天去了哪、老师讲了什么、自己看到什么 → 附上照片。之后每天重复这三步。

## 每次使用的常规流程

### Phase 1：素材清点

1. **确认要写哪一天**。用户没说清就先问；有多天混在一起时按天拆开写。
2. **检索录音**：在知识库检索 `第X天` 或 `第X天_地点`，列出命中的录音条目并读转写。没有录音也能写，只是细节靠口述，要提前说明。
3. **确认图片**（默认模式 B）：
   > "照片可以直接发我，我插到终稿里。还没整理好就先出带占位符和图片需求清单的版本（模式 A），之后发我补进去。"
   - 已给图 → 模式 B；表示稍后补 → 模式 A；明确不要图 → 无图版。
4. **读取当天对应的指导书内容**（站点段落 + 思考问题），从步骤 3 的索引直接跳转，不用整本重读。

### Phase 2：信息整合与核对

1. **先把用户口述整理成时间线**：路线顺序、几个点位、每个点位讲的是哪类内容（地质地貌/水文/产业/城市/人文）、自己的观察与疑问。这是全文骨架，写之前先在对话里用几行复述给用户确认（内容复杂或口述跳跃时必做；口述清晰可跳过）。
2. **用录音补细节**：地名、数据（高程/面积/年代/比例）、专业术语的原始表述、师生问答要点。转写里的听错、缺漏，用指导书或常识校正，并在交付说明里点出来。
3. **用指导书补背景与问题**：站点成因机制、区域背景，以及"思考问题"→ 转化为记录里的问题。
4. **用动员大会 PPT 校口径**：项目名称、实习目的与任务要求、纪律与提交要求，避免写出与要求不符的表述。
5. **必要时联网检索**：见下节规则，只用于核实硬数据与专有名称。
6. **多条录音合并**：按讲解先后或点位逻辑合并成一条当天时间线，能判断时区分上午/下午。

**确认门（可跳过）**：关键信息不全（不知道是哪位老师讲、日期地点对不上、口述与录音明显冲突）或用户要求先确认时，先给一份**关键信息确认单**（日期、地点、老师、各点位主题、待核数据、问题清单），确认后再动笔。用户说过"直接出成品"或内容简单无歧义时跳过。

### Phase 3：按模板撰写

读 `references/template-spec.md`，按字段细则写。

- **基本信息**：项目名称/专业年级/学号/姓名/时间/地点/上课老师/学习方式。学号、姓名、专业年级用户没提供就**留空**，交付时提醒补填，绝不编造或按示例填充。
- **听课记录**：按讲解逻辑分段，一段一个话题；保留地名、数据、术语原话；有价值的师生问答用"问：…／答：…"简要复现；口述里"我记得老师说……"这类模糊内容，能用录音落实的就落实，落实不了就写成定性表述，不要编具体数字。
- **观察到的现象和发现的问题**：先是现场可见的现象（用户口述+照片能印证的），再是问题——优先取指导书该站点的思考问题，其次是老师现场抛出但未展开的问题，再次是用户自己提的疑问。

### Phase 4：生成 Word

用 `ima-doc` 技能（python-docx）生成：

- 严格还原知识库模板的表格结构与字段顺序（`template-spec.md` 有逐字段说明；**模板与说明不符时以知识库模板为准**，并在交付时提醒同步修订说明文件）；
- 文件名 `实习过程记录_第X天_地点.docx`（多点位用主导地点或"XX-XX"连写）；
- 模式 B：按 `references/image-workflow.md` 把照片插到对应位置，插完**逐张检查**是否成功、位置是否正确；
- 保存到 `/workspace/outputs/`。

### Phase 5：交付

- 模式 B / 无图版：给下载链接 + 简述结构、图片位置、需补填的个人信息 + **待核项清单**（联网没核实到的数据、转写可疑处）。
- 模式 A：占位版链接 + **图片需求清单**（编号、建议内容、插入位置、拍摄提示），说明"拍好发我，替换占位符出终稿"。

## 事实与口径规则

### 冲突时的优先级

| 顺序 | 来源 | 用途 |
|---|---|---|
| 1 | 用户当次口述 + 现场照片 | 主线：走了哪、讲了什么、看到什么、问什么 |
| 2 | 老师讲解录音转写 | 补细节、术语原话、数据、师生问答 |
| 3 | 实习指导书 | 站点背景、实习要求、"思考问题" |
| 4 | 动员大会 PPT | 项目名称、目标与任务口径 |
| 5 | 联网检索 | 公开数据核实、背景补全 |

- 口述与录音不一致 → 以录音为准，并在交付说明里指出改了哪里。
- 录音与指导书不一致 → 以实地说法为准，标注"与指导书表述不同"。
- 联网结果与前面冲突 → **不覆盖**，标"待核"，写进交付清单让用户定。
- 任何一方都没有的信息 → 留白或定性表述，不补细节。

### 联网检索规则

允许检索，但只做三件事：核实硬数据（高程、面积、长度、年代、储量、产量、政策文件名称与年份）、确认专有名称的规范写法、补一句公开背景。要求：

- 优先政府/主管部门/学术文献/官方媒体；单一自媒体来源不采信。
- 同一数字至少两处来源一致才写进正文；只有一处就写"约"或放进待核清单。
- 联网内容不得替换或改写老师现场讲解，只做补充与校正。
- 交付说明里列出"联网核实过的内容"，让用户一眼看到哪些不是来自现场。

## 补充图片流程（后续单独触发）

1. 确认对应哪一天（按文件名、地点、上下文）。
2. 拿到当时的记录文档（用户重传或从 `/workspace/outputs/` 读）。
3. 模式 A → 按 `image-workflow.md` 把占位符换成实际图片；模式 B 终稿要加图 → 对应位置插入并重排。
4. 重新生成 Word 并交付，说明共几张、插在哪、图注是什么。

## 示例

**示例 1（标准流程，模式 B）**
用户："今天第 5 天，上午天子山下午袁家界，老师讲了峰林发育和节理，我在观景台看到岩层近水平，[3 张照片]" → 检索 `第5天` 录音转写 → 整理时间线并复述确认 → 录音补御笔峰数据与师生问答 → 指导书补"张家界地貌与喀斯特峰林差异"的思考问题 → 生成带图 Word → 交付 + 提醒补学号姓名 + 列出待核项。

**示例 2（只有录音，用户没口述）**
用户："帮我写第 7 天的记录，照片晚点给" → 检索 `第7天_龙脊梯田`、`第7天_灵渠` 两条转写 → 以转写为主线按上午/下午合并 → 生成占位版 + 图片需求清单 → 交付时明确提示"哪些内容是你个人观察、需要你补一句" → 用户补图补描述后出终稿。

**示例 3（补图）**
用户："这是第 2 天株洲博物馆的照片，帮我补进去" → 匹配第 2 天记录 → 确认每张图对应段落 → 插图重排 → 交付。
