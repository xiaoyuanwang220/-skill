# 图片处理 SOP（模式 B 嵌入 / 模式 A 占位与补图）

## 一、模式 B：动笔前拿到照片，直接嵌入终稿

### 1. 接收与盘点照片

- 照片经对话上传进入平台的上传目录（常见为 `/workspace/uploads/`，实际路径以当前环境为准，先用目录列表确认），先列出清单：文件名、格式、尺寸/朝向。
- 与用户确认**每张照片的插入位置和说明**：如"这张御笔峰远景放听课记录第2段后，图注'天子山御笔峰远景（摄于观景台）'"。用户没说位置时，根据内容判断并在交付说明中列出插图方案让用户复核。
- 格式支持 jpg/png 等常见格式直接用；heic 等苹果格式先转 jpg（可用 `sips` 或 Pillow 转换）。

### 2. python-docx 嵌入方法

```python
from docx import Document
from docx.shared import Cm

doc = Document()

# 方式一：插入到指定段落位置
# 定位目标段落后，在该段落后新建段落插入图片
run = p.add_run()
run.add_picture('/workspace/uploads/photo1.jpg', width=Cm(12))

# 方式二：单元格内插图（本模板中图片放单元格内）
cell = table.cell(3, 0)  # 听课记录单元格
para = cell.add_paragraph()
run = para.add_run()
run.add_picture('photo.jpg', width=Cm(12))
```

**尺寸规范**：横图宽 10–12cm，竖图宽 6–8cm（或高 8cm 左右），同组多图可并排（表格布局或 tab 分隔），保证不撑破单元格。分辨率过低的图（<800px 宽）缩小展示，不强行拉大。

**图注**：图片下一段居中、小五号、灰字或加括号，格式如 `图1 御笔峰远景（摄于观景台）`。用户没给图注就按内容拟一个，交付时说明可改。

### 3. 嵌入后自检

- 逐张确认图片确实插入（重新打开文档检查 inline_shapes 数量与顺序）；
- 确认位置正确（图随文走：现象描述段后放现场照片，人物讲解图放听课记录段后）；
- 单元格内图片不撑破表格布局。

## 二、模式 A：占位版 + 图片需求清单

### 1. 占位符写法

在 Word 对应插入位置写一个明显占位段：

> 【图片占位：图1 御笔峰远景——插入位置：听课记录第2段后】

或做成浅色边框表格行，明确"此处插图"。占位符必须**编号+内容+位置**三要素齐全，用户照单拍图不会错位。

### 2. 图片需求清单（交付时附上）

| 编号 | 建议图片内容 | 插入位置 | 拍摄提示 |
|---|---|---|---|
| 图1 | 御笔峰远景全景 | 听课记录第2段后 | 站观景台向西拍，避开人流 |
| 图2 | 沉积岩层理特写 | 观察到的现象第1条旁 | 顺光拍，含参照物（人/标尺）示比例 |

清单条数 = 占位符条数，一一对应。

### 3. 补图流程（用户后续发来照片时）

1. 确认天数/地点，找到记录文档（用户重传或从 `/workspace/outputs/` 读取）；
2. 用 python-docx 打开，定位占位符段落，删除占位文字所在 run，在同段插入图片（或删除占位段、在原位新建段落插图）；
3. 加图注，检查图随文走、不撑破表格；
4. 重新保存交付（覆盖或加 `_终稿` 后缀）。

## 三、注意事项

- 用户的原照片**不修改不删除**，`/workspace/uploads/` 里保留原件；Word 中嵌入的是副本。
- 交付说明中列出：共几张图、分别插在哪、图注是什么，便于用户核对。
